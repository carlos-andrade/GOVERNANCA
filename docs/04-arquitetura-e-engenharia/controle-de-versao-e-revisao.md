# Controlo de versão e revisão

- Usar Git para histórico rastreável.
- Preferir branch e pull request para alterações relevantes; documentar emergências e revisão posterior.
- Descrever motivação, âmbito, risco, testes e rollback.
- Nunca incluir chaves, tokens, palavras-passe ou dumps pessoais desnecessários.
- Ativar proteção de branches, revisão e checks apropriados quando a plataforma e permissões permitirem.
- Rever o diff e verificar os resultados dos checks.
- Releases identificam versão e artefactos; não sobrescrever sem rastreabilidade.

Este documento recomenda controlos; não prova que qualquer proteção ou pipeline esteja ativo.
